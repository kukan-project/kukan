# ADR-024: GA4 によるアクセス統計

## ステータス

承認済み（2026-05-25）

## コンテキスト

KUKAN をインターネットに公開する場合、データセットの閲覧数・ダウンロード数・検索キーワードといったアクセス統計を管理画面で確認したいという要件がある。CKAN には `tracking_summary` による閲覧・ダウンロード計測機能があったが、KUKAN では設計書・スキーマともにアクセス統計は一切スコープ外であった。

### 課題

1. **利用状況が見えない**: どのデータセットが活用されているか、どんなキーワードで検索されているかがわからない
2. **自前実装のコスト**: ページビューやダウンロードのカウントを DB に記録する方式は、テーブル設計・書き込み負荷・ボット除外ロジックが必要で重い
3. **LGWAN との両立**: 閉域網（LGWAN 等）ではインターネットへの通信が不可能なため、外部サービス依存の機能は条件付きで無効化する必要がある

### 要件

- インターネット公開環境で、データセットの閲覧数・ダウンロード数・検索キーワードをランキング形式で確認できる
- LGWAN / オフライン環境では無効化でき、アプリケーションの動作に影響しない
- 既存のブランドオーバーライドレイヤー（ADR-023）と整合する設定方式
- 計測インフラの自前構築を避け、運用コストを最小化する

## 決定

**Google Analytics 4（GA4）を計測基盤とし、フロントエンドに gtag.js を条件埋め込み、管理画面では GA4 Data API からデータを取得して表示する。**

## 根拠

### 代替案の比較

| 方式                     | メリット                           | デメリット                                      | 判定     |
| ------------------------ | ---------------------------------- | ----------------------------------------------- | -------- |
| **GA4 Data API（採用）** | 計測インフラ不要、豊富な指標、無料 | 外部依存、データ遅延（数時間〜48h）、LGWAN 不可 | **採用** |
| 自前カウント（DB）       | LGWAN 対応、リアルタイム           | テーブル設計・書き込み負荷・ボット除外が必要    | 見送り   |
| Matomo セルフホスト      | LGWAN 対応、GA4 相当の機能         | Docker サービス追加、運用コスト増               | 見送り   |
| GTM 経由                 | タグ管理の柔軟性                   | データカタログに不要な複雑性、追加 JS ロード    | 見送り   |

**GA4 を選択した理由:**

1. **インターネット公開限定**: LGWAN 閉域網では GA4 は使えないが、アクセス統計の需要自体がインターネット公開環境に限定される
2. **計測インフラ不要**: gtag.js を埋め込むだけでページビュー・ファイルダウンロード・サイト内検索が自動計測される
3. **ダウンロードの自動捕捉**: GA4 Enhanced Measurement はリンククリック時の拡張子ベース検出に加え、KUKAN では `DownloadButton` コンポーネントでカスタムイベントも送信する
4. **検索キーワードの自動計測**: 検索フォームが `GET /dataset?q=...` で遷移するため、GA4 Enhanced Measurement の「サイト内検索」が URL の `q` パラメータを自動検出する
5. **GTM 不採用**: データカタログは広告タグやヒートマップを動的に差し替える必要がなく、デプロイ者≒管理者のためタグの非エンジニア管理も不要。パフォーマンスと制御の単純さを優先して gtag.js 直接埋め込みとする

### 2 段階構成

本機能は 2 つの独立したサブタスクで構成される。

#### 4a: gtag.js 条件埋め込み（フロントエンド計測）

**`brandConfig` による制御:**

`BrandConfig` 型にオプショナルフィールドとして `gaMeasurementId` を追加する。ADR-023 のブランドオーバーライドレイヤーにそのまま乗る形で、環境変数は介さない。フォーク側が `brand-config.ts` に直接 Measurement ID を記述する。

```typescript
export interface BrandConfig {
  // ...既存フィールド
  gaMeasurementId?: string | null
}
```

本体デフォルト（GA4 無効）:

```typescript
export const brandConfig: BrandConfig = {
  // ...既存設定
  gaMeasurementId: null,
}
```

フォーク側（GA4 有効）:

```typescript
export const brandConfig: BrandConfig = {
  // ...既存設定
  gaMeasurementId: 'G-XXXXXXXXXX',
}
```

環境変数を使わない理由: GA4 Measurement ID はデプロイ環境ごとに変わるが、`brand-config.ts` 自体がフォークごとの設定ファイルであり、ADR-023 の方針（フォーク側の変更を `src/brand/` に集約）に沿って `brand-config.ts` で管理するのが自然である。

**layout.tsx での条件埋め込み:**

`brandConfig.gaMeasurementId` が truthy な場合のみ、Next.js の `<Script>` コンポーネントで gtag.js をロードする。`strategy="afterInteractive"` でページ表示を阻害しない。

**計測対象:**

| 計測項目             | 方式                          | 実装                                                                     |
| -------------------- | ----------------------------- | ------------------------------------------------------------------------ |
| ページビュー         | GA4 自動計測                  | gtag.js ロードのみ                                                       |
| ファイルダウンロード | カスタムイベント              | `DownloadButton` の `onClick` で `gtag('event', 'file_download', {...})` |
| サイト内検索         | Enhanced Measurement 自動検出 | URL の `?q=` パラメータから自動計測（追加コード不要）                    |

**ダウンロードイベントの設計:**

KUKAN のダウンロード URL（`/api/v1/resources/:id/download`）には拡張子がないため、GA4 Enhanced Measurement の自動検出では捕捉されない。`DownloadButton` コンポーネント（全ダウンロード操作が集約されている唯一の箇所）で明示的にカスタムイベントを送信する。

```typescript
gtag('event', 'file_download', {
  file_name: displayFilename,
  link_url: href,
  // KUKAN 固有のカスタムパラメータ
  dataset_name: datasetNameOrId,
  resource_id: resourceId,
  format: format,
})
```

GA4 の `file_download` イベント名を使用することで、GA4 管理画面の標準レポートでもデータが表示される。

#### 4b: 管理画面の統計ダッシュボード（GA4 Data API）

**認証:**

GCP サービスアカウントの JSON キーで GA4 Data API に認証する。

| 環境変数               | 用途                                   | 未設定時                   |
| ---------------------- | -------------------------------------- | -------------------------- |
| `GA4_PROPERTY_ID`      | GA4 プロパティ ID（数値）              | 統計ページに設定案内を表示 |
| `GA4_CREDENTIALS_JSON` | サービスアカウント JSON キー（文字列） | 同上                       |

**統計項目:**

| ランキング             | GA4 ディメンション                                           | GA4 メトリクス    | URL パターン                            |
| ---------------------- | ------------------------------------------------------------ | ----------------- | --------------------------------------- |
| データセット閲覧数     | `pagePath`                                                   | `screenPageViews` | `/dataset/{name}` でフィルタ            |
| リソース閲覧数         | `pagePath`                                                   | `screenPageViews` | `/dataset/.../resource/{id}` でフィルタ |
| リソースダウンロード数 | `customEvent:file_download` の `dataset_name`, `resource_id` | `eventCount`      | カスタムイベントから集計                |
| 検索キーワード         | `searchTerm`                                                 | `eventCount`      | Enhanced Measurement 自動収集           |

**期間指定:**

- プリセット: 過去 7 日 / 30 日 / 90 日 / 1 年
- カレンダー: 自由に開始日・終了日を指定

**ランキング表示:**

- ページネーション付き（GA4 Data API の `offset` / `limit` で制御）

**データ取得:**

- GA4 Data API をリアルタイムに呼び出し、lru-cache（既存インフラ）でキャッシュ
- キャッシュ TTL: 1 時間（GA4 Data API のデータ遅延を考慮し、頻繁な再取得は無意味）
- 将来的にバッチ取得 + DB 保存への移行も可能だが、当面はリアルタイム取得で十分

**未設定時の動作:**

- 管理画面のナビゲーションに統計メニューは常に表示
- `GA4_PROPERTY_ID` / `GA4_CREDENTIALS_JSON` が未設定の場合、ページ内に設定手順の案内を表示
- LGWAN 環境でもエラーにはならず、案内表示のみ

### 対象ユーザー

sysadmin ロールのみ。組織管理者（admin ロール）への組織単位フィルタは将来の拡張として位置づける。

### API アクセス統計

ブラウザを経由しない API 直接呼び出しの統計は GA4 では計測不可能。これは別タスクとして切り出し、サーバーサイドでの計測（ログ集計または DB カウント）を別途検討する。

### GA4 Data API のクォータ

| 制限                               | 値     |
| ---------------------------------- | ------ |
| 1 プロパティあたりの日次リクエスト | 25,000 |
| 同時リクエスト                     | 10     |

lru-cache（TTL 1 時間）により、管理者が何度ページをリロードしても API 呼び出しは最大 24 回/日/クエリパターン。クォータ超過のリスクは極めて低い。

### フロントエンド・バックエンド構成

```
apps/web/src/
  app/
    layout.tsx                         ← gtag.js 条件埋め込み（4a）
    dashboard/admin/
      analytics/
        page.tsx                       ← 統計ダッシュボード（4b）

  components/
    download-button.tsx                ← gtag カスタムイベント追加（4a）
    analytics/
      analytics-ranking.tsx            ← ランキング表示コンポーネント（4b）
      analytics-date-range.tsx         ← 期間選択コンポーネント（4b）

packages/api/src/
  routes/
    admin.ts                           ← GET /admin/analytics/* エンドポイント追加（4b）
  services/
    analytics-service.ts               ← GA4 Data API 呼び出し + キャッシュ（4b）
```

## 実装計画

### Step 1: 4a — gtag.js 条件埋め込み

1. `BrandConfig` 型に `gaMeasurementId?: string | null` を追加
2. `brand-config.ts` のデフォルト値に `gaMeasurementId: null` を設定
3. `layout.tsx` に `<Script>` で gtag.js を条件埋め込み
4. `DownloadButton` に `onClick` でカスタムイベント送信を追加

### Step 2: 4b — 管理画面統計ダッシュボード

6. `@google-analytics/data` パッケージを `packages/api` に追加
7. `analytics-service.ts` で GA4 Data API 呼び出し + lru-cache を実装
8. `/admin/analytics/*` API エンドポイントを追加
9. フロントエンドの統計ダッシュボードページを実装（ランキング表 + 期間選択）
10. 未設定時の案内表示を実装
11. ドキュメントサイトに GA4 セットアップガイドを追加

## 結果

### メリット

1. **計測インフラ不要**: GA4 に計測を委ね、KUKAN 側は読み取り専用。DB テーブル追加・書き込み負荷・ボット除外ロジックが不要
2. **自動計測の活用**: ページビューとサイト内検索は gtag.js を埋め込むだけで計測開始。追加コードはダウンロードイベントのみ
3. **段階的実装**: 4a（タグ埋め込み）だけでも GA4 管理画面でデータが確認できる。4b は後から追加可能
4. **brandConfig 統合**: ADR-023 のブランドオーバーライドレイヤーに自然に統合され、フォーク側の設定変更も `brand-config.ts` に集約
5. **LGWAN 安全**: 環境変数未設定時は一切の外部通信が発生しない

### デメリット

1. **外部依存**: Google のサービスに依存する（GA4 廃止時は代替が必要）
2. **データ遅延**: GA4 のデータは数時間〜最大 48 時間遅延する。リアルタイムの統計は取得できない
3. **API アクセス統計の欠落**: ブラウザを経由しない API 呼び出しは計測できない（別タスクで対応）
4. **GA4 セットアップの手間**: デプロイ者が GA4 プロパティ作成・サービスアカウント設定を行う必要がある

### 中立

1. **GA4 管理画面との重複**: 4b で管理画面に統計を表示するが、GA4 管理画面でも同じデータは確認可能。4b の価値は「KUKAN の管理画面だけで完結する」利便性にある
2. **カスタムディメンション**: `dataset_name`, `resource_id` は GA4 のカスタムディメンションとして登録が必要。セットアップガイドで手順を説明する
