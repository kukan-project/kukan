# ADR-057: 素直な表の XLSX をテーブルとして解釈する（判定は規則、AI は提案に限る）

## ステータス

**提案（Proposed）— 実データでの割合を測ってから着手を判断する**

XLSX のうち、**見出し 1 行と矩形のデータだけでできた「素直な表」**を、Interpret ステージで
テーブルとして解釈し、CSV/TSV と同じくプレビュー Parquet を作る。以降は表プレビュー・
行レベル差分（ADR-043 層 2）・OData（ADR-055）・MCP の `/query`（ADR-032）にそのまま乗る。

**表とみなすかどうかの判定は、決まった規則で行う。** AI には判定させない。AI の役割は、
規則で表とみなせなかったファイルについて表の範囲と見出しを**提案**することに限る。提案は
規則で検算し、人が確かめて確定値として保存する。以後の解釈は確定値から決定的に行う。

正本（アップロードされた XLSX のバイト列）には手を触れない。Parquet は ADR-046 の言う
「解釈」の産物である。

本 ADR は ADR-046 の残課題 5（解釈の生産者を差し替え可能な口にする）のうち、XLSX の構造検出を
具体化する。ADR-053 §2 が「Excel はデータとして使えるようにならない」と明記した代償に、
別の骨格で答えるものでもある。

## コンテキスト

### 1. いま、XLSX はテーブル経路に入っていない

Interpret は `isCsvFormat` で分岐し（`apps/worker/src/pipeline/steps/interpret.ts`）、
XLSX/XLS はテーブルとして解釈されない。その結果、

| 経路                 | CSV/TSV                        | XLSX/XLS                          |
| -------------------- | ------------------------------ | --------------------------------- |
| プレビュー           | 表（Range 配信 + DuckDB-WASM） | Office Online Viewer（10MB まで） |
| 列のスキーマ         | 版ごとに記録                   | なし                              |
| 行レベル差分（層 2） | あり（主キー指定で変更行追跡） | なし                              |
| OData / MCP `/query` | あり                           | なし                              |
| 全文索引             | 表のテキスト                   | officeparser で取り出したテキスト |
| AI 抄録（ADR-053）   | 表の材料                       | 原本をそのまま渡す                |

自治体のオープンデータでは、同じ表が XLSX だけで公開されていることが少なくない。
それらはカタログ上「何のデータか」は分かっても、「データとして触れる」ことができない。

### 2. 表かどうかは、フォーマットではなく中身で決まる

CSV は形式そのものが表である。XLSX はそうではない。同じ拡張子の中に、

- 見出し 1 行と矩形のデータだけの、素直な表
- 表の上にタイトルや単位の注記があり、下に出典や注が付く表
- 多段の見出し、結合セル、途中の小計行を持つ、いわゆる神エクセル
- 帳票・申請様式・図表など、そもそも表でないもの

が混在する。したがって「XLSX なら表」とはできず、**版ごとの解釈結果として「表だった /
表でなかった（その理由）」を記録する**必要がある。これは CSV が既に持つ仕組みと同じである —
`resource_version.schema` が空のスキーマ（`NO_TABLE`）と `reason`（`no-columns` /
`too-many-columns` など）で「解釈したが表は無かった」を表している。

### 3. 構造の誤推定は、UX ではなくデータ完全性の問題

ADR-053 §2 はこう書いた。**ヘッダー行の判定が再実行で 1 行ずれれば、行レベル差分は全行が
変更されたと報告する。** 範囲を誤って読めば、注記の行がデータに混ざり、OData で配られ、
MCP の集計に入る。

誤って表にした場合の害は、表にし損ねた場合の害よりずっと大きい。表にし損ねても、今の扱い
（Office Viewer とテキスト索引）が続くだけだからである。判定は**迷ったら表とみなさない**側に
倒さなければならない。

### 4. 既にある部品

| 部品                   | 実体                                                   | 本 ADR での使い道                               |
| ---------------------- | ------------------------------------------------------ | ----------------------------------------------- |
| CSV の解釈             | `interpret/csv.ts` の `interpretCsv`（DuckDB sniffer） | 表の範囲を CSV にしてから渡す（決定 4）         |
| タイトル行の検出       | `interpret/csv-title-rows.ts` の `countTitleRows`      | 表の上の 1 セルだけの行を落とす                 |
| 注記行の除去           | `interpret/csv.ts` の `trimFooter`                     | 表の下の出典・注を落とす                        |
| 表が無かったことの記録 | `NO_TABLE` + `reason`                                  | 規則に外れた理由を残す                          |
| 人が確定した列の設定   | `resource.column_settings`（主キー、ii-c で確定型）    | 確定した表の範囲を置く（決定 7）                |
| 版への凍結             | 版は作成時の設定を凍結する（仕様書 §6.7）              | 確定した範囲も版に凍結する                      |
| 版同一性の入力         | `sameVersionIdentity`                                  | 範囲の確定は版を作る（ii-c の確定型と同じ扱い） |

## 検討した選択肢

### 判定を誰が行うか

#### A) AI に判定させる

原本（または左上 N×M のセルと結合マップ）をモデルに渡し、「表か、表ならどの範囲か、見出しは
何行か」を答えさせる。崩れた表にも対応できるので、表として拾える割合は最も高い。

**採らない。** 同じ入力から同じ答えが出る保証がなく、パイプラインの決定性（ADR-046）を壊す。
もっともらしい誤りを返したとき、それを機械的に検出する手段がない。閉域網（`AI_TYPE=none`）
では機能ごと使えなくなる。そして素直な表の判定は、セルグリッドを見れば規則で確かめられる —
AI に委ねても精度は上がらず、コストと非決定性だけが増える。

#### B) 規則だけで判定する

結合セルの有無・見出しの行数・矩形性・列の型の揃い方を、セルグリッドから機械的に確かめる。
決定的で、理由を説明でき、閉域網でも同じに動く。

**素直な表には十分だが、崩れた表を救えない。** 多段の見出しや 1 シートに複数の表が並ぶ
ファイルは、規則を広げても意味を読まなければ扱えない。

#### C) 規則で判定し、外れたものだけ AI が範囲を提案し、人が確定する — 採用

- 自動で表にするのは規則を通ったものだけ（B と同じ）
- 規則に外れたものについて、AI は表の範囲と見出しを**提案**する
- 提案は規則で**検算**する（その範囲に結合セルが無いか、列の型が揃うか）。通らない提案は捨てる
- 人が確かめて確定したものを確定値として保存し、以後はその値で決定的に解釈する

推論ではなく決定を残す形なので、再実行でぶれない。ADR-040 の「提案であって決定ではない」、
ADR-053 §2 の「提案 → 人の確認 → 確定値としての永続化」と同じ骨格である。
閉域網では AI の提案が無いだけで、人が範囲を指定する経路は残る。

### XLSX を読むパーサ

判定には**結合セルの情報**が要る。変換には値と型が要る。

| 候補                             | 結合セル                           | 備考                                                                     |
| -------------------------------- | ---------------------------------- | ------------------------------------------------------------------------ |
| DuckDB excel 拡張（`read_xlsx`） | 取れない（関数に結合の概念が無い） | 変換は速いが判定に使えない。拡張の事前 INSTALL が要る（閉域網対応）      |
| exceljs                          | 取れる                             | MIT、pure JS。XLS は読めない。ストリーミング読み取り時の結合情報は要確認 |
| SheetJS（xlsx）                  | 取れる（`!merges`）                | XLS も読める。npm レジストリ上の版は古く、配布は自前 CDN（供給経路が別） |

**この ADR では決めない。** スパイク（Step 0）で、実データの XLSX に対するメモリ使用量と
結合情報の取り方を確かめてから選ぶ。どれを選んでも pure JS か DuckDB 拡張であり、worker に
ネイティブ依存は増えない見込みである（増える場合は Dockerfile の copy-back が要る）。

## 決定（提案）

### 1. 正本は XLSX のまま。Parquet は解釈の産物

XLSX を CSV に変換して正本を差し替えることはしない。表として解釈できた版にだけ、プレビュー
Parquet とスキーマが付く。解釈の規則を後から変えても、正本は変わらず、再解釈で追従できる。

### 2. 「素直な表」の条件

次をすべて満たすとき、そのシートを表とみなす。

1. **表とみなせるシートが 1 枚だけ**である（他のシートは空）。1 リソース = 1 表という
   版と Lake の前提を崩さない
2. **データ範囲に結合セルが無い**。範囲の外（上のタイトル）の結合は、タイトル行として
   落とせるなら許す
3. **見出しが 1 行**で、見出しのセルがすべて埋まり、重複しない
4. **データが矩形**である — 見出しの列数の外に値が無い
5. タイトル行と注記行は、CSV と同じ規則（`countTitleRows` / `trimFooter`）で落とせる範囲に
   収まる

条件の細部（空行の扱い、見出しの前後の空列、しきい値）は実装仕様書で決める。

### 3. 外れたら今の扱いに戻し、理由を記録する

条件に外れた版は `NO_TABLE` とし、`reason` に外れた条件を記録する（例: `merged-cells`、
`multiple-sheets`、`multi-row-header`、`not-rectangular`）。プレビューは Office Viewer のまま、
全文索引も今どおり。**表にし損ねることは失敗ではなく、表でなかったという解釈結果**である。

`reason` の分布は、規則をどこまで広げるか・AI の提案に投資するかを決める材料になる。

### 4. 変換は CSV を経由して既存の CSV 解釈に渡す

表の範囲を、UTF-8 の中間 CSV に書き出して `interpretCsv` に渡す。

- セルは**表示書式ではなく生の値**で書く（`1,234` ではなく `1234`）
- 日付として書式設定されたセルは ISO 8601 で書く（シリアル値のまま渡さない。1900 年
  うるう年の扱いもここで吸収する）
- 数式は**キャッシュされた計算結果**を書く。計算結果を持たない数式が範囲にあれば、表と
  みなさない（`reason: 'uncached-formulas'`）

CSV を経由する理由は、型推定・注記行の除去・ii-c の確定型の適用（`read_csv` の `types`
宣言、仕様書 §6.3）が、すべて CSV の解釈に 1 か所で実装されているからである。XLSX 専用の
経路を作ると、これらが 2 系統に分かれる。

代償として、XLSX のセルが持つ型情報（文字列として入力された `00123` など）は sniffer に
渡らず、数値と推定され得る。これは CSV でも起きることで、ii-c の確定型で直す。セルの型を
`types` の初期値として渡すかどうかは実装仕様書で判断する。

中間 CSV は解釈の作業ファイルであり、保存しない。

### 5. XLS（旧形式）は当面対象外

BIFF 形式の XLS は読めるパーサが限られ（SheetJS のみ）、公開データでの比率も下がっている。
Step 0 の実測で比率が高ければ再検討する。

### 6. 表かどうかは、フォーマットではなく版のスキーマで分岐する

今は表プレビュー・索引・AI 抄録・提案の材料（`suggest/materials.ts`）が `isCsvFormat` で
分岐している。XLSX は版ごとに表だったりそうでなかったりするので、**XLSX については
「版にスキーマがあるか」で分岐する**必要がある。

- プレビュー: スキーマがあれば表、無ければ Office Viewer（両方を切り替えられるようにするかは
  UI の判断）
- 全文索引: 今の officeparser のテキストのまま変えない
- AI 抄録: スキーマがあれば表の材料に寄せられる（ADR-053 §3「原本を渡すのは、そうしないと
  中身が取れないときだけ」）。寄せるかどうかは別途判断する

### 7. AI の提案と人の確定（Step 3）

規則に外れた版について、編集者の操作を起点に（自動ではなく）AI が表の範囲を提案する。

- 入力: 左上 N×M のセル値と結合マップ（原本全体は渡さない）
- 出力: シート名・データ範囲（A1 形式）・見出しの行数
- 検算: 提案された範囲に決定 2 の条件 2〜4 を当てる。通らなければ提示しない
- 確定: 人が確かめた範囲を `resource.column_settings` に置く（主キー・確定型と同じ場所。
  人だけが書き、worker は書かない）
- 適用: 以後の版は確定した範囲で解釈する。版は作成時の範囲を凍結する。範囲の確定・変更は
  版同一性の入力に加わり、新しい版を作る（ii-c の確定型と同じ扱い、仕様書 §6.5）

多段の見出しは、確定時に人が列名を与える形で扱う（AI は列名の案も出せる）。

**同じ骨格で、AI を使わず人が範囲を指定する経路（Step 2）を先に作れる。** AI の提案はその
入力欄を埋める補助にすぎない。

## 段階

| 段階   | 内容                                                                  | 前提           |
| ------ | --------------------------------------------------------------------- | -------------- |
| Step 0 | 実データの XLSX で、決定 2 の条件を満たす割合と `reason` の分布を測る | なし           |
| Step 1 | 規則だけの判定と変換（決定 1〜6）                                     | Step 0 の結果  |
| Step 2 | 人が範囲を指定して確定する UI と、確定値の適用                        | ii-c（確定型） |
| Step 3 | AI による範囲の提案と検算                                             | Step 2         |

Step 0 はコードを書かずに判定だけを行う計測で、パーサの選定（上の表）もここで行う。
割合が低く、しかも外れ方が「タイトル行が数行ある」程度に偏っていれば、Step 1 の規則を
広げれば足りる。多段の見出しや複数の表が多ければ、Step 2・3 の価値がはっきりする。

## 影響

- `apps/worker/src/pipeline/steps/interpret.ts` に XLSX の分岐が加わる（パーサ依存が 1 つ増える）
- `resource_version` の `reason` に XLSX 由来の値が加わる
- 表プレビュー・提案の材料など、`isCsvFormat` で分岐している箇所のうち XLSX を扱うものは、
  版のスキーマで分岐するよう改める
- Lake・OData・MCP は Parquet とスキーマを見るので、変更は要らない見込み
- 既存の XLSX 版は、再解釈で新しい解釈を得る。正本は変わらない。既存の版を一括で
  再解釈させる経路は実装仕様書で決める
- Step 2 以降: `column_settings` に表の範囲が加わり、版同一性の入力が 1 つ増える

## 未決事項

1. **パーサの選定**（Step 0）
2. **非表示の行・列**: 値としては存在するので含めるのが既定と考えるが、作業用の列を
   隠しているだけのファイルもある。Step 0 で実例を見て決める
3. **複数シートの選択**: 決定 2-1 は「表が 1 枚だけ」に限った。複数シートから 1 枚を選ぶのは
   Step 2 の確定値で扱えるが、複数の表を 1 リソースから出すことは、1 リソース = 1 表の前提を
   変える別の判断になる
4. **サイズ**: XLSX は ZIP 圧縮なので、100MB の入口に対して展開後はずっと大きくなる。
   解釈対象の上限を XLSX 用に別に持つかは Step 0 の測定で決める
5. **プレビューの切り替え**: 表として解釈できた XLSX で、Office Viewer への切り替えを残すか
