ベースパス: `/api/v1`

認証列の記号:

- **公開** — 認証不要
- **認証** — ログインまたは API トークンが必要
- **組織** — 組織の member / editor / admin のいずれか
- **sysadmin** — システム管理者のみ

:::note[PUT セマンティクス]
PUT エンドポイントは全フィールド置換です。リクエストに含めないフィールドは `null`（またはデフォルト値）にクリアされます。
既存値を保持するには、現在のデータを GET で取得し、変更を加えた全体を送信してください。
例外として、**下書き（draft）状態のデータセットへの PUT は部分更新**です（後述の「下書き（draft）」参照）。
:::

## データセット (packages)

| Method | Path                               | 説明                                                                         | 認証        |
| ------ | ---------------------------------- | ---------------------------------------------------------------------------- | ----------- |
| GET    | `/packages`                        | データセット一覧（検索・絞り込み対応）                                       | 公開        |
| POST   | `/packages`                        | データセット作成（`resources` 配列でリソース同時作成可）                     | 組織 editor |
| POST   | `/packages/drafts`                 | 下書き作成（全フィールド任意）                                               | 認証        |
| GET    | `/packages/{nameOrId}`             | データセット詳細                                                             | 公開        |
| PUT    | `/packages/{nameOrId}`             | データセット更新（active は全置換 / draft は部分更新、`resources` は対象外） | 組織 editor |
| DELETE | `/packages/{nameOrId}`             | データセット削除（active は論理削除 / draft は即時完全削除）                 | 組織 editor |
| POST   | `/packages/{nameOrId}/publish`     | 下書きを公開（`draft` → `active`）                                           | 組織 editor |
| POST   | `/packages/{nameOrId}/restore`     | 論理削除済みを復元                                                           | sysadmin    |
| POST   | `/packages/{nameOrId}/purge`       | 論理削除済みを完全削除                                                       | 組織 admin  |
| GET    | `/packages/{id}/resources`         | リソース一覧                                                                 | 公開        |
| POST   | `/packages/{id}/resources`         | リソース追加                                                                 | 組織 editor |
| PUT    | `/packages/{id}/resources/reorder` | リソース順序変更                                                             | 組織 editor |

### 主なクエリパラメータ（GET /packages）

| パラメータ         | 説明                                                     |
| ------------------ | -------------------------------------------------------- |
| `q`                | 検索クエリ（キーワードまたは自然文。ハイブリッド検索）   |
| `semantic`         | `false` でキーワード一致のみ（デフォルト: `true`）       |
| `offset` / `limit` | ページネーション（最大 100）                             |
| `organization[]`   | 組織で絞り込み                                           |
| `groups[]`         | カテゴリーで絞り込み                                     |
| `tags[]`           | タグで絞り込み                                           |
| `res_format[]`     | リソース形式で絞り込み（例: `CSV`）                      |
| `license_id[]`     | ライセンスで絞り込み                                     |
| `state`            | `active` / `deleted` / `draft`（`draft` は要認証・後述） |
| `my_org`           | 自分が `editor` 以上の組織に限定                         |
| `private`          | 非公開データを含む                                       |
| `sort_by`          | `updated` / `created` / `name`                           |
| `sort_order`       | `asc` / `desc`                                           |
| `include_facets`   | ファセット情報を含める                                   |

### 例: データセット検索

```bash
curl "https://your-kukan-site/api/v1/packages?q=人口&organization[]=stat-bureau&limit=10"
```

### 下書き（draft）

データセットは下書きとして作成し、公開条件を満たしてから公開できます。
下書きは公開されるまで検索・一覧（CKAN 互換 API 含む）に一切現れません。

**作成** — `POST /packages/drafts`（要認証）:

全フィールド任意です。`name` を省略すると `untitled-xxxxxxxx` 形式のプレースホルダーが
自動生成されます（プレースホルダーのままでは公開できません）。作成時に `ownerOrg` を
指定する場合は、その組織の editor 権限が必要です。

```bash
curl -X POST https://your-kukan-site/api/v1/packages/drafts \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"title": "作業中のデータセット"}'
```

**公開** — `POST /packages/{nameOrId}/publish`:

`draft` → `active` の一方向遷移です（公開後に下書きへ戻す操作はありません）。
以下の 3 つが未設定の場合は `400` を返します。

- `name` が明示的に設定済み（自動生成プレースホルダーのままは不可）
- `ownerOrg` が設定済み
- `licenseId` が設定済み

権限はデータセット更新権限と同一で、`ownerOrg` の組織の editor 権限が公開時点で
再検証されます。公開済み（`active`）への再実行は許可され、公開時の検索インデックス
同期を再実行します（同期が失敗した場合のリトライ入口として冪等）。

**一覧** — `GET /packages?state=draft`（要認証）:

自分が作成した下書きと、所属組織（editor 以上）の下書きのみが返ります。
対応フィルタは `q` / `name` / `organization[]` / `private` / `sort_by` / `sort_order` /
`offset` / `limit`。`tags[]` / `groups[]` / `res_format[]` / `license_id[]` /
`creator_user_id` / `my_org` / `include_facets` を指定すると `400` になります。
削除が途中で失敗した行（削除未完了）も一覧に含まれます。

**取得・更新・削除**:

- 詳細取得は `GET /packages/{id}?state=draft`（要認証・下書きの閲覧権限が必要）
- draft への `PUT` は**部分更新**です。リクエストに含めたキーのみ適用され、明示的な
  `null` はそのフィールドをクリアします。`name: null` はプレースホルダーを再生成して
  「名前未設定」に戻し、`ownerOrg: null` は組織をクリアします（いずれも公開が再び
  ブロックされます）。`active` への `PUT` は従来どおり全置換です
- draft への `DELETE` はゴミ箱を経由せず**即時完全削除**します（復元不可）。削除が
  途中で失敗した場合は、同じ `DELETE` の再実行が完全削除を完了します

### スキーマとデータクエリ

CSV/TSV リソース（パイプラインでプレビュー Parquet を生成済み・≤50MB）は、**列スキーマの取得**と
**読み取り専用 SQL クエリ**ができます。AI エージェント向けには MCP の `get_resource_schema` /
`query_resource` ツールも同等の機能を提供します。

**スキーマ取得** — `GET /resources/{id}/schema`:

```json
{
  "id": "…",
  "queryable": true,
  "schema": {
    "rowCount": 1688,
    "columns": [
      { "name": "市区町村（発生地）", "type": "string", "nullable": true, "nullCount": 3 },
      {
        "name": "重量制限",
        "type": "integer",
        "nullable": false,
        "nullCount": 0,
        "stats": { "min": "600", "max": "1350" }
      }
    ]
  }
}
```

クエリ不可のリソース（非対応フォーマット・未処理）は `queryable: false`, `schema: null` を返します。
`type` は `integer` / `float` / `boolean` / `string` / `date` / `timestamp`。`stats` は数値列のみで、
整数の min/max は十進文字列です。

**データクエリ** — `POST /resources/{id}/query`:

```bash
curl -X POST https://your-kukan-site/api/v1/resources/{id}/query \
  -H 'Content-Type: application/json' \
  -d '{"sql": "SELECT \"市区町村（発生地）\" AS city, count(*) AS n FROM data GROUP BY 1 ORDER BY n DESC LIMIT 3"}'
```

```json
{
  "id": "…",
  "columns": ["city", "n"],
  "rows": [
    { "city": "足立区", "n": "117" },
    { "city": "江戸川区", "n": "110" },
    { "city": "大田区", "n": "86" }
  ],
  "rowCount": 3,
  "truncated": false,
  "elapsedMs": 31
}
```

クエリのルール:

- データは `data` という名前のテーブルとして参照します。列名に空白や非 ASCII を含む場合は二重引用符で囲みます。
- 単一の `SELECT` / `WITH` 文のみ。`INSERT` / `UPDATE` / `DELETE` / `CREATE` / `DROP` / `ATTACH` / `COPY` / `PRAGMA` 等の書き込み・DDL は拒否されます。
- 使い捨ての in-memory DuckDB 上で実行され、ファイル・URL・拡張ロード等の外部アクセスは全面的に禁止されます。

制限とエラー:

| 項目             | 値                                   |
| ---------------- | ------------------------------------ |
| 最大行数         | 10,000（超過時は `truncated: true`） |
| 最大結果サイズ   | 5 MB                                 |
| 実行タイムアウト | 15 秒（`408`）                       |
| 同時実行         | 1（超過時 `429`）                    |

| エラー | 状況                                              |
| ------ | ------------------------------------------------- |
| `400`  | SQL 不正・非 SELECT・長さ超過・クエリ不可リソース |
| `404`  | リソース不存在 / 非公開で権限なし                 |
| `408`  | 実行タイムアウト                                  |
| `429`  | 同時クエリ上限                                    |

### バージョンと差分

リソースのファイルが差し替わると、差し替え前の内容が**版**として保存されます。内容が変わらない
限り版は増えません。

**版の一覧** — `GET /resources/{id}/versions`（新しい順）:

```json
{
  "id": "…",
  "versions": [
    {
      "version": 2,
      "origin": "upload",
      "state": "active",
      "isLive": true,
      "purgeFallsBackTo": 1,
      "format": "CSV",
      "size": 20481,
      "hash": "…",
      "schema": { "rowCount": 1688, "columns": [] },
      "noTableReason": null,
      "keyColumns": ["注文番号", "明細番号"],
      "created": "2026-08-01T09:12:44.000Z",
      "purgedAt": null
    }
  ]
}
```

| フィールド         | 説明                                                                                                                              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `origin`           | `upload`（明示的な差し替え） / `fetch`（外部 URL の取得時点）                                                                     |
| `state`            | `active` / `superseded`（巻き戻しで外れた） / `purging` / `purged`                                                                |
| `isLive`           | そのリソースが今配信している版か。`version` や `state` からは決まりません                                                         |
| `purgeFallsBackTo` | この版をパージしたとき配信が戻る版。`isLive` の版だけに入ります（他の版のパージでは配信が動かないため）                           |
| `format`           | その版が確定した時点のフォーマット。リソースのラベルを変えても変わりません                                                        |
| `schema`           | その版の列スキーマ（表形式のみ）。版ごとに凍結されます                                                                            |
| `noTableReason`    | 表が作れなかった理由（`no-columns` / `too-many-columns` / `too-large`）                                                           |
| `keyColumns`       | その版の行を同定した主キー列。主キーなしで読まれた版は `null`。リソースの現在の設定は「**次の**版が何で読まれるか」なので別物です |

完全削除済み（`purged`）の版は記録として残りますが、`size` / `hash` / `schema` / `keyColumns` は
`null` になり、
`purgedAt` が入ります。ダウンロードは `404` を返します。`keyColumns` を伏せるのは、主キーが内容の
持つ列にしか設定できず、その名前が伏せた `schema` の部分集合になるためです（`format` は閉じた語彙
なので残ります）。**パージの理由は返しません** — 消した内容についての自由記述であり、この
エンドポイントはリソースと同じ範囲で読めるためです。誰が何をいつどんな理由でパージしたかは監査
ログにあります。

**差分** — `GET /resources/{id}/versions/{v}/diff?from={v'}`（既定の `from` は直前の版）:

対象データセットの **editor 権限**が必要です（両方のスナップショットを全走査するため、公開
エンドポイントにはしていません）。

```json
{
  "available": true,
  "from": 1,
  "to": 2,
  "schemaChanged": false,
  "keyed": false,
  "addedRows": 42,
  "removedRows": 3,
  "sampleAdded": [{ "市区町村": "足立区", "件数": "117" }],
  "sampleRemoved": []
}
```

- **`keyed` は両端が同じ主キーで読まれたときだけ `true`** になり、そのとき `changedRows` と
  `sampleChangedAfter` / `sampleChangedBefore` が加わります（2 つの見本は位置で対応し、変更前の側は
  **実際に値が変わった列だけ**を持ちます — 主キーは一致しているので両側にあり、値が動かなかった列は
  含まれません。見本のセルは表示用に切り詰められるため、両者を比べても変わったかどうかは判定できません。
  列が変更前の側にあるかどうかが答えです）。主キーが指定されていない・両端で違う場合は `false` で、
  **1 行の書き換えは追加 1 行 + 削除 1 行として現れます**（行を同定できないため）
- 列構成が変わった版どうしは `{"schemaChanged": true, "schemaDiff": {"added": [], "removed": [], "retyped": []}}`
  を返し、行差分は行いません
- 差分を出せない場合は
  `{"available": false, "reason": "…", "from": …, "to": …, "reasonVersion": …}` を返します。
  `reason` は `no-previous-version` / `not-ingested` / `purged` / `key-missing` / `key-null` /
  `key-not-unique`。後ろの 3 つは**指定した主キーがその版の行を同定できず取り込まれなかった**ことを
  意味します。`not-ingested` は原因ではありません — 片端に行レベルのスナップショットが
  無く、主キー由来の理由も無い、というだけで、版の作成から取り込みが走るまでの通常の待ち時間も
  含みます。**原因が版側に記録されていてもこの理由になります** — 解釈が決める 3 つは
  `noTableReason` にあり、そちらが答えます
- `reasonVersion` は **その理由がどちらの版についてのものか**です。**開いた版とは限りません** —
  主キーを直した次の版を開けば断られたのは直前の版ですし、`not-ingested` も片端の性質です。
  比較対象が無い（`no-previous-version`）場合と、どちらの端が墓標でも同じく比較が成立しない
  パージの場合だけ `null` になります
- SQL はサーバーが版番号だけから組み立てます。`POST /resources/{id}/query` のサンドボックスとは
  別経路で、利用者の SQL がこの領域に到達することはありません
- 応答は `Cache-Control: private, max-age=60, must-revalidate`。取得できなかった応答は
  キャッシュされません

| エラー | 状況                                  |
| ------ | ------------------------------------- |
| `401`  | 未認証                                |
| `403`  | 対象データセットの editor 権限が無い  |
| `404`  | リソースまたは版が存在しない          |
| `408`  | 差分の実行タイムアウト                |
| `429`  | DuckDB の同時実行上限（クエリと共用） |

**版の完全削除** — `POST /resources/{id}/versions/{v}/purge`（sysadmin 限定）:

理由が必須で、監査ログに記録されます。版を確保して `202` を返し、実際の消去はワーカーが
非同期に行います。同じ版への再実行は冪等です。

```bash
curl -X POST https://your-kukan-site/api/v1/resources/{id}/versions/2/purge \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"reason": "個人情報の混入"}'
```

**巻き戻し** — `POST /resources/{id}/revert`:

処理を中止し、リソースの内容を指定の版へ戻します。

```json
{ "restoreTo": 2, "ifLiveRevision": "018f…-…-…" }
```

- `restoreTo` は**戻し先の版番号**です（何段戻すかではありません）。`null` はリソースを
  ファイルの無い状態にします
- `ifLiveRevision` は `GET /resources/{id}/pipeline-status` が返す `live_revision` です。
  これにより、応答を組み立てている間に別のアップロードが入った場合、その内容を巻き戻して
  しまうことがありません
- 同じ `pipeline-status` が `revert_target`（戻し先の既定値）も返します

巻き戻した後、プレビューと検索索引が古いままになることがあります。その場合は
`POST /resources/{id}/run-pipeline` に `{"rebuildOnly": true}` を付けて再構築します
（外部 URL からの再取得は行われません）。

### 列設定

そのリソースの行を同定する主キー。指定すると版差分が変更行を数えるようになります（`keyed: true`。
指定が無ければ 1 行の書き換えは追加 1 行 + 削除 1 行として現れます）。3 つとも **editor 権限**が
必要です — これはデータの説明ではなく、人が列について確定した決定だからです。

**読み取り** — `GET /resources/{id}/column-settings`:

```json
{
  "id": "…",
  "primaryKey": ["注文番号"],
  "carried": false,
  "schema": {
    "rowCount": 1688,
    "columns": [{ "name": "注文番号", "type": "string", "nullCount": 0, "unique": true }]
  }
}
```

- `schema` は **live 版**が凍結した解釈です — `PUT` が検証に使うのと同じ列なので、この一覧から
  選んだ主キーが「その列は無い」で断られることはありません
- `unique` は単独で行を同定できる列を示します。その列を選ぶなら確認は不要です。**組み合わせに
  ついては何も言いません** — 複合キーは実データを読まないと分かりません
- `carried` は、最新の生きている版がまだ `primaryKey` で読まれていない間 `false` です。
  主キーを確定してから再構築が着くまでの**通常の状態**であって、異常ではありません

**確認** — `POST /resources/{id}/column-settings/check`、ボディ `{"primaryKey": [...]}`:

```json
{ "id": "…", "checked": true, "primaryKey": ["注文番号"], "fault": "key-not-unique" }
```

- `fault` は通る場合 `null`、断られる場合は `key-missing` / `key-null` / `key-not-unique`
- `{"checked": false, "reason": "no-preview" | "preview-stale"}` は**確かめられなかった**という
  意味です（読める解釈が無い）。**エラーではありません** — `PUT` は内容を一切読まないので、
  この状態でも主キーは確定できます
- 単一列キーは版が凍結した列ごとの数から、複合キーは解釈の Parquet を読んで答えます

**確定** — `PUT /resources/{id}/column-settings`、ボディ `{"primaryKey": [...] | null}`:

```json
{ "id": "…", "primaryKey": ["注文番号"], "queued": true }
```

- `[]` と `null` はどちらも「主キーなし」です。ボディの側で 1 つの綴りに正規化されます
- 列は**指定した順序で保持されます**。ただし**行の照合は順序によりません** — キーを使う操作は
  いずれも列を AND で並べるためです。それでも順序は記録されるキーの一部なので、同じ列を別の順序で
  指定すると別のキーとして扱われ、版が 1 つ作られます
- **主キーの確定は版を作ります。** 版とは「このバイト列を、この読み方で」であり、主キーは読み方の
  一部だからです。バイト列は動かないので、新しい版は同じ内容の複製を所有します。`queued` はその版を
  発行する再構築が投入されたことを示し、`null` は再構築が不要だったことを示します。**`false` は
  設定は保存できたが再構築を投入できなかったことを示します** — 書き込みと投入は別々に判断されるので、
  **同じボディを再送すれば修復できます**。設定と最新版の食い違いを掃除する仕組みは無いため、`false` を
  無視すると、どの版もその主キーで読まれないまま残ります
- **既に層 2 に入っている版を新しい主キーで読み直すことはしません。** 境界は版そのものであり、
  それをまたぐ差分は行全体の比較に縮退します
