KUKAN は [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) に準拠したサーバーエンドポイントを提供します。Claude、ChatGPT、その他の MCP 対応 AI エージェントからデータカタログの検索・閲覧が可能です。

## エンドポイント

```
POST /api/mcp
```

Streamable HTTP トランスポートを使用したステートレスモードで動作します。

## 接続方法

### Claude Code

コマンドで追加します。

```bash
claude mcp add --transport http kukan https://your-kukan-site/api/mcp
```

プロジェクトの `.mcp.json` に書く場合は、`type` を `http` にします。

```json
{
  "mcpServers": {
    "kukan": {
      "type": "http",
      "url": "https://your-kukan-site/api/mcp"
    }
  }
}
```

所属組織の非公開データセットも扱う場合は、[API トークン](/ja/api/authentication/)をヘッダーで渡します（コマンドなら `--header "Authorization: Bearer kukan_..."`、`.mcp.json` なら `"headers": { "Authorization": "Bearer kukan_..." }`）。

### Claude Desktop / claude.ai

設定の「コネクタ」から、カスタムコネクタとして `https://your-kukan-site/api/mcp` を追加します（使えるプランは Claude のヘルプセンターを参照してください）。

- 接続は利用者の PC からではなく Anthropic のクラウドから行われます。**インターネットから届かないサイト（閉域網・VPN の内側など）には接続できません**。その場合は、利用者の PC から接続する Claude Code などのクライアントを使ってください
- カスタムコネクタには API トークンのヘッダーを設定できないため、公開データセットだけを扱います

### curl でのテスト

```bash
curl -X POST https://your-kukan-site/api/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2025-03-26",
      "capabilities": {},
      "clientInfo": { "name": "test", "version": "0.1" }
    }
  }'
```

## 提供ツール

すべてのツールは読み取り専用です。認証済みユーザーの権限に基づいて、非公開データセットへのアクセスが制御されます。

| ツール                 | 説明                                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| `search_datasets`      | キーワードまたは自然文でデータセットを検索（ハイブリッド検索）。どのファイルが一致したかも返す             |
| `get_dataset`          | データセットの詳細情報を取得（リソース一覧含む）                                                           |
| `get_resource`         | リソース（ファイル）のメタデータ・URL・AI による説明を取得                                                 |
| `get_resource_schema`  | リソースの列スキーマ（列名・型・行数・統計）と OData 配信の可否を取得。CSV/TSV のみ                        |
| `query_resource`       | リソースのデータに読み取り専用 SQL（SELECT/WITH のみ）を実行。CSV/TSV のみ                                 |
| `get_document_outline` | 文書の目次（見出しとそのページ、ブックのシートと行）を取得。PDF/Word/PowerPoint/Excel/一太郎               |
| `get_document_section` | 文書の本文を、ページ・スライド・シート・見出しを指定して、出典付きで取得。PDF/Word/PowerPoint/Excel/一太郎 |
| `list_organizations`   | 組織の一覧を取得                                                                                           |
| `list_groups`          | グループ（カテゴリ）の一覧を取得                                                                           |
| `list_tags`            | タグの一覧を取得                                                                                           |

## ツール詳細

### search_datasets

データカタログを検索します。キーワードのほか自然文でも検索でき、
意味の近いデータセットも結果に含まれます（ハイブリッド検索）。

データセットが複数のファイルを持つ場合、**どのファイルが一致したか**を `Matched files:` として
返します。各行には一致の根拠が付きます — `in its name or description`（メタデータ）、
`in its contents`（本文）、`in its AI-written description`（AI による説明）、
`by meaning 0.42`（意味。数値は類似度）。**意味で一致した場合、検索語はそのファイルの
どこにも現れません**ので、語を探しに行っても見つからない点に注意してください。
一致が多いときは先頭 5 件を挙げ、残りは件数で示します。
各結果には組織・説明（先頭 200 文字）・フォーマット（データベースから取得）も付きます。

| パラメータ     | 型       | 必須 | 説明                                               |
| -------------- | -------- | ---- | -------------------------------------------------- |
| `q`            | string   | Yes  | 検索キーワードまたは自然文                         |
| `organization` | string   | No   | 組織名（slug）でフィルタ                           |
| `tags`         | string[] | No   | タグ名でフィルタ                                   |
| `semantic`     | boolean  | No   | `false` でキーワード一致のみ（デフォルト: `true`） |
| `offset`       | number   | No   | スキップ件数（デフォルト: 0）                      |
| `limit`        | number   | No   | 最大件数（デフォルト: 10、最大: 50）               |

### get_dataset

データセットの詳細情報を取得します。リソース一覧は公開ページと同じ並びで、セクションが
始まる位置に `[セクション名]` の見出し行が入ります。`/` の入れ子は公開ページと同じ深さで
字下げされ、配下のリソースも見出しより 1 段下がります。

| パラメータ | 型     | 必須 | 説明                              |
| ---------- | ------ | ---- | --------------------------------- |
| `nameOrId` | string | Yes  | データセット名（slug）または UUID |

### get_resource

リソースのメタデータを取得します。アップロード済みファイルの場合はダウンロード URL を返します。
セクションに入っているリソースは `Section:` 行を持ちます。
本文を抽出済みの文書（PDF・Word・PowerPoint・Excel・一太郎。2007 より前の Office 形式を含む）は `Document text:` 行を持ち、
`get_document_outline` と `get_document_section` で読めることを示します（全ページがスキャンの文書はその旨）。

サイトで [AI による説明](/ja/data-admin-guide/#ai-による説明抄録)が有効な場合、末尾に説明文が
付きます。あわせて**そのファイルのどこまでを読んで書いたか**（`read the column layout and the
first 100 of 1200 rows` など）と、**どの版を説明しているか**が返ります。ファイルが差し替え済みで
説明が追いついていない場合は `describes v1, and the file is now v2` のように示されるため、
古い説明を最新と取り違えることはありません。説明が生成されなかった場合は理由が返ります。

| パラメータ | 型     | 必須 | 説明          |
| ---------- | ------ | ---- | ------------- |
| `id`       | string | Yes  | リソース UUID |

### get_resource_schema

リソースの列スキーマ（列名・型・null 許容・行数、数値列の min/max）を取得します。リソースに
主キーが確定されていれば `Primary key:` 行として併記されます。CSV/TSV で
プレビュー生成済みのリソースのみクエリ可能です。クエリ可能な場合のみ、出力にクエリ用
テーブル名 `data` とクエリ例が含まれ、エージェントはこれを見てから SQL を書けます。
クエリ不可の場合（プレビューが無い・現在の内容を反映していない）は、列一覧は参考として
返しつつクエリ案内を省きます。

**OData フィードの可否も併せて返します。** 配信される場合はフィード URL（末尾 `/Rows`）と、
行を同定する列 — 主キーがその役を果たすか、KUKAN が `RowId` 列を足すか、足すならその理由 — を
示します。1 行が大きく読み込みに失敗しうる表には、その注意も付きます。
配信されない場合は理由（見出しが OData 識別子にならない、同名の列がある、データセットが
非公開・下書きなど）を返します。**SQL が撃てることと OData で読めることは一致しません**ので、
取得方法を選ぶ前にこの行を見てください。

| パラメータ | 型     | 必須 | 説明          |
| ---------- | ------ | ---- | ------------- |
| `id`       | string | Yes  | リソース UUID |

### query_resource

リソースのデータに対して読み取り専用 SQL（`SELECT` / `WITH` のみ）を実行し、結果を Markdown
テーブルで返します。データは `data` というテーブルとして参照します。`get_resource_schema` で列名・型を
確認してから利用してください。

| パラメータ | 型     | 必須 | 説明                                           |
| ---------- | ------ | ---- | ---------------------------------------------- |
| `id`       | string | Yes  | リソース UUID                                  |
| `sql`      | string | Yes  | 単一の SELECT/WITH 文（`data` テーブルを対象） |

使い捨ての in-memory DuckDB 上で実行され、外部アクセス禁止・行数/バイト/時間の上限付きです。列名に
非 ASCII を含む場合は二重引用符で囲みます。制限・エラーの詳細は REST の `/resources/{id}/query` を参照。

### get_document_outline

文書の目次を取得します。何を読むかを決めるために、`get_document_section` の前に呼びます。

- **見出し**：PDF のしおり、Word の見出しスタイル、スライドのタイトルを、階層の字下げ付きで並べます。
  それぞれに、その見出しの範囲のページ（スライド）が付きます（`pages 15–18  １－１－３ 職員に関する事項`）
- **ブック**：見出しの代わりにシートを並べ、シート名と行の範囲を付けます
- **ページ数と読めないページ**：ページ（スライド・シート）の範囲と、読める文字の無いページ（スキャンなど）、一部の文字が読めないページ（PDF のフォントが文字の対応を持たない字形。本文からは外しています）を示します
- 先頭には `get_document_section` と同じ出典が付きます

2007 より前の Word（DOC）と一太郎は、読み取れる見出しを持たないので、本文は 1 ブロックになります。

全ページがスキャンで本文の無い文書でも、ページ数・見出し・読めないページは返します。
長い目次は約 12,000 字で切り（見出しは 1 件 120 字まで、読めないページの一覧はその 4 分の 1 まで）、残りの件数を示します。そのときは `from`・`to` でページを絞って見てください。

| パラメータ | 型     | 必須 | 説明                                       |
| ---------- | ------ | ---- | ------------------------------------------ |
| `id`       | string | Yes  | リソース UUID                              |
| `from`     | number | No   | 最初のページ・スライド・シート（1 始まり） |
| `to`       | number | No   | 最後のページ・スライド・シート             |

### get_document_section

KUKAN が文書（PDF・Word・PowerPoint・Excel・一太郎。2007 より前の Office 形式を含む）から抽出した本文を、ファイルの中の位置で指定して
取得します。位置はページの範囲（PDF はページ、プレゼンテーションはスライド、ブックはシート）、
見出し、またはその両方で指定します。AI のモデルは呼ばず、ファイルにある本文をそのまま返します。

応答の先頭には、引用に使う出典が付きます — リソース名とデータセット名、リソースページとファイルの
URL（PDF は `#page=N` を付けるとそのページで開きます）、フォーマット、版。本文はブロックごとに、
ページ（印刷上のページ番号が違う場合はそれも）・スライド・シートと行、その上の見出しで示されます
（`--- page 12 (iv) · 第2章 > 人口`）。読める文字の無いページ（スキャンなど）は、省かずにその旨を
示します。一部の文字が読めないページは、本文から外した字数を示します。ファイルが差し替えられ、本文の抽出がまだ追いついていない場合は、`Version:` の代わりに
本文の版（`Text from: version 1`）と今のファイルの版（`Current file version: 2`）を分けて示します。
引用には本文の版を使ってください。

見出しは、指定した文字列を含むものに一致します。大文字・小文字、全角・半角、空白の違いは無視し、
シート名にも一致します。Word のファイルはレイアウトするまでページを持たないため、見出しでだけ
指定できます。`第1章 > 概要` のように見出しを `>` でつなぐと、ある見出しの下の見出しを指定できます。
一致するものが無い場合は、その文書のページの範囲を返し、`get_document_outline` で目次を見るよう案内します。

| パラメータ  | 型     | 必須 | 説明                                                                       |
| ----------- | ------ | ---- | -------------------------------------------------------------------------- |
| `id`        | string | Yes  | リソース UUID                                                              |
| `from`      | number | No   | 最初のページ・スライド・シート（1 始まり）                                 |
| `to`        | number | No   | 最後のページ・スライド・シート（その番号を含む）                           |
| `heading`   | string | No   | 本文の上にある見出し、またはシート名の一部                                 |
| `max_chars` | number | No   | 返す本文の文字数（デフォルト: 8,000、最大: 32,000）                        |
| `cursor`    | string | No   | 前の応答の末尾にあったカーソル。`from`・`to`・`heading` はカーソルから取る |

長い範囲は途中で切り（できるだけ改行の位置で）、続きを読むためのカーソルを末尾に付けます。
文書の抽出がやり直されると、それ以前のカーソルは使えなくなります。

## 認証

MCP エンドポイントは KUKAN の認証システムと連携しています。

- **未認証**: 公開データセットのみアクセス可能
- **認証済み**: 所属組織の非公開データセットもアクセス可能
- **システム管理者**: すべてのデータセットにアクセス可能

認証する場合は、API トークンを `Authorization: Bearer kukan_...` ヘッダーで送ってください（[認証](/ja/api/authentication/)）。

## 技術仕様

- **プロトコル**: MCP (Model Context Protocol)。版は初期化時にクライアントと交渉します（2024-11-05 以降の版に対応）
- **トランスポート**: Streamable HTTP
- **モード**: ステートレス（セッション管理なし）
- **レスポンス形式**: JSON-RPC 2.0
