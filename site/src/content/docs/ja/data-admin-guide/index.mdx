## データセットの作成

データセットは**下書き（draft）**として作成し、リソースとメタデータが揃ってから公開します。
下書きは公開するまで検索結果・データセット一覧には一切表示されません。

1. ダッシュボードにログイン
2. 「下書きを作成」をクリック — 名前（URL 識別子）・組織・ライセンスは後から設定できます
3. 編集ページでリソースを追加（ファイルアップロード / 外部 URL）— パイプライン処理は下書きの間も実行されるため、公開前にプレビューを確認できます
4. メタデータを整えて「保存して公開」をクリック

### 基本情報

| 項目                 | 説明                                       | 公開時必須 |
| -------------------- | ------------------------------------------ | :--------: |
| 名前（URL スラッグ） | 英数字・ハイフン・アンダースコア・ピリオド |     ○      |
| タイトル             | 表示用のタイトル                           |     -      |
| 説明                 | データセットの詳細な説明                   |     -      |
| 組織                 | データを所有する組織                       |     ○      |
| ライセンス           | データのライセンス                         |     ○      |
| 公開 / 非公開        | 非公開にすると組織メンバーのみ閲覧可       |     -      |

「公開時必須」の項目は下書きの間は未設定でもかまいませんが、3 つすべてが設定されるまで公開できません。
名前を入力しない間は自動生成の識別子が仮に使われます（そのままでは公開できません）。

### タグ

タグを追加してデータセットを分類できます。
既存のタグから選択するか、新しいタグを作成できます。

### 下書きの管理と削除

下書きはダッシュボードの「下書き」タブで管理します。編集できるのは作成者とサイト管理者、
組織を設定した後はその組織の編集者以上です。

下書きの削除はゴミ箱を経由せず、リソースのファイルごと**完全に削除**されます（復元不可）。
削除処理が途中で失敗した場合、その下書きは「削除未完了」として一覧に残り、
「削除を再試行」で完全削除をやり直せます。

## リソースの管理

リソースはデータセットに紐づくファイルや URL です。

### リソースの追加

- **ファイルアップロード** — ブラウザから直接アップロード（最大 100 MB）
- **外部 URL** — 外部サイトのファイル URL を指定

### 対応フォーマット

CSV、TSV、JSON、GeoJSON、XML、PDF、Excel など多数のフォーマットに対応しています。

アップロードされたファイルは自動的にパイプライン処理され、以下が実行されます。

- テキストファイルのエンコーディング検出・変換
- CSV/TSV ファイルの Parquet 変換（テーブルプレビュー用）
- ZIP ファイルのマニフェスト生成

## バージョン管理

リソースのファイルが差し替わるたびに、差し替え前の内容が**版**として保存されます。
過去の版はダウンロードでき、CSV/TSV なら版の間で何行増減したかを確認できます。

版が作られるのは、**内容が実際に変わったとき**だけです。外部 URL を再取得しても中身が
同じなら版は増えず、リソースの処理状況に「内容が同じため、新しい版は作成されていません」と
表示されます。

### バージョン履歴を見る

リソースの編集画面に「**バージョン履歴**」があります。新しい版が上に並び、各行に版番号・
作成日時・サイズ・取得元（**アップロード** / **取得時点**）が出ます。

各版はその時点のファイルをそのままダウンロードできます。ファイル名には版番号が付きます。

### 差分を見る

版の行の「**差分**」から、直前の版との差分をその場で取得できます（開いたときに計算されるので、
一覧を開くだけでは走りません）。

- **追加 N 行 / 削除 N 行**と、それぞれの代表的な行が表示されます
- **「変更 N 行」は表示されません。** 行を同定する主キーを指定していないため、1 行の書き換えは
  「追加 1 行 + 削除 1 行」として現れます。推測で変更履歴を作らない方針です
- **列構成が変わった場合**（列の増減・型の変化・並び替え）は、行を突き合わせられないため
  「列構成が変わったため、行単位の差分は取得できません」と表示されます

差分を取得できるのは **CSV/TSV（50 MB 以下）**の版どうしだけです。取得できない場合は理由が
表示されます。

| 表示                                                                           | 意味                                     |
| ------------------------------------------------------------------------------ | ---------------------------------------- |
| 最初の版のため、比較対象がありません。                                         | v1 には比較相手がありません              |
| この版は差分の対象外です（表形式でない、または機能導入前に取得された版です）。 | PDF 等、または移行前に作られた版         |
| 一方の版が完全削除されているため、差分を取得できません。                       | どちらかの版が完全削除（パージ）済みです |

### 処理の中止・巻き戻し

差し替えたファイルが間違っていたときのために、破壊の度合いが違う操作が 3 段あります。
それぞれ明示的に選びます。

| 操作                 | 現在の内容               | 版                       | 権限         |
| -------------------- | ------------------------ | ------------------------ | ------------ |
| **中止**             | そのまま                 | そのまま                 | 組織 editor  |
| **中止して巻き戻す** | 直近の保存済みの版に戻る | 戻り先より上は履歴に残る | 組織 editor  |
| **この版を完全削除** | 最新版なら直前の版に戻る | 内容を消去し記録だけ残る | サイト管理者 |

**中止して巻き戻す**は、差し替え後のファイルを直近の版へ戻します。前の版が無い場合、
リソースはファイルを持たない状態になります（メタデータは残ります）。

プレビューと検索用の内容は、**巻き戻しと同時に破棄され、戻した内容から自動で作り直されます**
（作り直しはバックグラウンドで走るため、反映まで少し時間がかかります）。破棄か作り直しの
開始に失敗したときだけ警告が表示されるので、その場合は「プレビューと索引を再構築」で
仕上げてください。

### 版の完全削除（パージ）

個人情報の混入など、**内容そのものを消さなければならない**場合に使います。**サイト管理者のみ**が
実行でき、**理由の入力が必須**で監査ログに記録されます。

- 正本ファイルと、差分のために保持している行データを直ちに削除します
- **同じ内容を持つ版が他にもある場合、その内容は消えません。** 版はそれぞれ自分の複製を持つため、
  1 つを完全削除しても他の版はその内容を配り続けます。最新版を完全削除して直前の版に戻ったとき、
  その版が同じ内容なら**リソースが同じ内容を配り直します**。確認ダイアログが該当する版番号を
  示すので、そちらも消す必要があれば個別に完全削除してください
- ストレージのバージョニングを使う環境では、退避された旧オブジェクトがその保持期間
  （既定 30 日）の経過後に消滅します
- 最新版を完全削除すると、リソースの内容は直前の版に戻ります。過去の版が無い場合は
  ファイルのない状態になります
- 履歴には「削除済み」の行と削除理由が残ります。**取り消せません**

### 導入時の一度きりの移行

バージョン管理を導入した直後は、それ以前からあるリソースに版が付いていません。
サイト管理者のダッシュボードに「**バージョンの補完**」が表示されるので、実行してください。

- **層 1**: 版を持たないリソースの現在のファイルを v1 として記録します（再取得・再インデックスは
  行いません）
- **層 2**: 表形式リソースの現在の版を差分表示に取り込みます。取り込むと、次の更新から
  差分を確認できます

残件が両方とも 0 になると、この項目は表示されなくなります。**実行しないまま差し替えると、
それ以前の内容は版として残らずに失われます。**

## AI によるメタデータ提案

リソースを追加してパイプライン処理が完了すると、編集画面の「**AI にメタデータを提案させる**」ボタンから、タイトル・説明・タグや各リソースの名前・説明を AI に提案させられます（サイトで AI 機能が有効な場合のみ。[システム管理者ガイド](/ja/system-admin-guide/#サイト管理設定ランタイム設定)参照）。

- **前提**: パイプライン処理が完了したリソースが 1 つ以上あること。無い場合はボタンが無効になり、リソースのアップロードを促します。
- **使い方**:
  1. 編集画面で「AI にメタデータを提案させる」をクリックします（生成に数十秒〜数分かかることがあります）
  2. ダイアログで「データセット」「リソース」のセクションごとに、現在値と AI の提案を並べて確認します
  3. 採用したいフィールドの採用トグルを ON にします（**初期状態はすべて OFF**。既存の値を上書きするかは任意です）
  4. 必要なら、採用した提案値をその場で編集できます
  5. 「採用」をクリックします
- **反映のされ方**: タイトル・説明・タグは編集フォームに反映され、**データセットを保存すると確定**します。リソースの名前・説明は**採用と同時に保存**されます。
- **提案の材料**: CSV/TSV は列や先頭データの内容から、PDF・Excel などはファイル名・フォーマットから提案します。生成される文章の言語は表示言語に従います。
- 提案内容はどこにも保存されません（採用した値だけが通常の更新として保存されます）。乱用防止のため 1 ユーザーあたりの実行回数に上限があります。

## 組織の管理

組織はデータセットの所有単位です。

### メンバー管理

組織の管理者は、メンバーの追加・削除・役割変更ができます。

| 役割     | データセット閲覧 | データセット編集 | 削除 | 復活 / 完全削除 | メンバー管理 |
| -------- | :--------------: | :--------------: | :--: | :-------------: | :----------: |
| メンバー |        ○         |        -         |  -   |        -        |      -       |
| 編集者   |        ○         |        ○         |  ○   |        -        |      -       |
| 管理者   |        ○         |        ○         |  ○   |        ○        |      ○       |

削除済みデータセットはダッシュボードの「削除済み」タブで組織メンバーが閲覧できます。復活・完全削除は管理者のみ実行可能です。

### 組織の削除・復元・完全削除

組織管理ページでは「公開」「削除済」のカードで表示を切り替えられます（「削除済」の閲覧はサイト管理者のみ）。

- **削除（論理削除）**: 組織をゴミ箱へ移動します。配下に**アクティブなデータセットが無いこと**が条件で、残っている場合は先に削除または別組織へ移管してください（残っている間は削除ボタンが無効になります）。
- **復元**: 「削除済」の組織を元に戻します（サイト管理者のみ）。
- **完全削除（パージ）**: 組織と、そのゴミ箱内の削除済みデータセットをファイルごと**完全に消去**します（取り消し不可。サイト管理者のみ）。処理はバックグラウンドのジョブで非同期に実行されるため、完了するまで一覧に残って見えることがあります。

## カテゴリー（グループ）

カテゴリーは組織を横断してデータセットを分類する仕組みです。
データセット作成時にカテゴリーを指定できます。

### カテゴリーのメンバー管理

カテゴリーにもメンバー管理があり、組織と同様の役割構成です。

| 役割     | カテゴリー閲覧 | データセット追加 | メンバー管理 |
| -------- | :------------: | :--------------: | :----------: |
| メンバー |       ○        |        -         |      -       |
| 編集者   |       ○        |        ○         |      -       |
| 管理者   |       ○        |        ○         |      ○       |
