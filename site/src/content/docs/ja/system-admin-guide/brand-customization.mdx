KUKAN をフォークして自組織向けにカスタマイズする際のガイドです。
変更は段階的に行えます。軽い変更から順に試してください。

## カスタマイズの範囲

フォーク側で変更するファイルは以下の 2 箇所に限定されます。

| ディレクトリ             | 内容                                        |
| ------------------------ | ------------------------------------------- |
| `apps/web/src/brand/`    | 設定・CSS 変数・コンポーネント override     |
| `apps/web/public/brand/` | ロゴ、ファビコン、OG 画像などの静的ファイル |

これ以外のファイルは変更しないでください。本体の更新を取り込む際にコンフリクトが発生します。

## Tier 1: 色・サイズの変更

`brand/theme.css` に CSS 変数を記述するだけで、サイト全体の配色やサイズを変更できます。

```css
/* apps/web/src/brand/theme.css */
:root {
  --primary: 142 64% 32%; /* メインカラー（HSL） */
  --primary-foreground: 0 0% 100%; /* メインカラー上のテキスト色 */
  --kukan-header-height: 72px; /* ヘッダー高さ */
  --kukan-container-max-width: 1400px;
}
```

### 利用可能な CSS 変数

shadcn/ui 標準の変数と KUKAN 固有の変数（`--kukan-*` プレフィックス）が利用できます。全一覧は `apps/web/src/app/globals.css` を参照してください。

上書きしてよいかの判断がしやすいよう、各変数に**上書き区分**を付けています。

- **推奨** — ブランドに合わせて変更する想定の変数
- **注意** — 上書き可能ですが複数のコンポーネント・状態で共有されています。「用途と主な使用箇所」を確認し、デフォルトの明暗関係（淡色・濃色）を維持してください
- **非推奨** — UI の意味（エラー・成功・警告）を伝える変数。ブランド都合での変更は推奨しません

| 変数                                                      | 区分   | 用途と主な使用箇所                                                                                                                       |
| --------------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `--primary` / `--primary-foreground`                      | 推奨   | メインカラー。ボタン（default）、リンク、進捗バー、テキスト選択、チェックボックス等の選択状態                                            |
| `--highlight`                                             | 推奨   | 検索キーワードのハイライト（影響は検索結果表示のみ）                                                                                     |
| `--radius`                                                | 推奨   | 角丸の基準値（全コンポーネント）                                                                                                         |
| `--kukan-*`                                               | 推奨   | ヘッダー高さ・ロゴ高さ・コンテナ幅等のレイアウト値                                                                                       |
| `--background` / `--foreground`                           | 注意   | ページ背景・基本テキスト。サイト全体に波及                                                                                               |
| `--card` / `--popover`（各 `-foreground` 付き）           | 注意   | カード、およびドロップダウン・セレクト等のポップアップの背景とテキスト                                                                   |
| `--secondary` / `--secondary-foreground`                  | 注意   | secondary ボタン・バッジの背景。淡色前提                                                                                                 |
| `--muted` / `--muted-foreground`                          | 注意   | 補足テキスト（サイト内で最も使用箇所が多い変数）、プレースホルダー、スケルトン、淡色背景。淡色前提                                       |
| `--accent` / `--accent-foreground`                        | 注意   | **ホバー・選択状態の色**。outline / ghost ボタンのホバー、セレクト・ドロップダウンのフォーカス項目、ダイアログの閉じるボタン等。淡色前提 |
| `--border` / `--input`                                    | 注意   | 全コンポーネントの境界線・入力枠                                                                                                         |
| `--ring`                                                  | 注意   | フォーカスリング。キーボード操作の視認性に直結するため、背景とのコントラストを確保してください                                           |
| `--destructive` / `--destructive-foreground`              | 非推奨 | エラー・削除の意味色（destructive ボタン、フォームエラー、削除メニュー項目）。ベタ塗り背景と、その上のテキスト                           |
| `--success` / `--warning`                                 | 非推奨 | 成功・警告の意味色（アラート、パイプラインステータス、フォーム警告）。ボーダー・淡色背景・アイコンに使用                                 |
| `--success-tint-foreground` / `--warning-tint-foreground` | 非推奨 | 成功・警告の**淡色（/10〜/15）背景上**のテキスト色。ベタ塗り用ではありません                                                             |

### 上書き時のルール

配色を安全に差し替えるため、以下を守ってください。

1. **生トークンのみを上書きする** — `--primary` 等をそのまま再宣言します。`globals.css` の `--color-*`（Tailwind 連携用マッピング）は本体管理のため変更しないでください。
2. **HSL の裸トリプレット形式を維持する** — `--primary: 142 64% 32%;` のようにカンマなし・`hsl()` なしで記述します。hex 値や `hsl(...)` で包んだ値は動作しません。
3. **不透明度を焼き込まない** — 透過は使用側のユーティリティ（`bg-success/10` 等）で掛かります。トークンには不透明度 100% のベース色だけを入れてください。
4. **ペアはセットで更新し、コントラストを確認する** — `--primary` を変えたら `--primary-foreground` も更新し、コントラスト比 4.5:1 以上（WCAG AA）を確保します。`--success` / `--warning` を変えた場合、対応する `-tint-foreground` は**同系統の濃色**にし、`/15` の淡色背景上で 4.5:1 以上を確認します（`-foreground` と異なりベタ塗り背景用ではない点に注意）。
5. **`dark:` クラスを持ち込まない** — KUKAN のテーマトークンはライト専用です。override コンポーネントに `dark:` を書くと、OS がダーク設定のユーザーだけ表示が崩れます。
6. **override コンポーネントでも生パレット色を書かない** — `text-green-600` ではなく `text-success` のようにセマンティッククラスを使うと、後からの配色変更が `theme.css` 1 ファイルで済みます。

### 独自トークンの追加（`--brand-*`）

デザイナー指定の配色に、公式トークンの役割（主要色・強調色など）に当てはまらない独自色が含まれる場合は、`--brand-` プレフィックスの独自トークンを `brand/theme.css` に追加できます。

```css
/* apps/web/src/brand/theme.css */
:root {
  --brand-accent-green: 183 29% 87%;
  --brand-link: 183 79% 28%;
}
```

- **`--brand-*` はフォーク専用の名前空間です** — 本体は `--brand-*` を定義も参照もしないため、本体更新と衝突しません。逆に `--kukan-*` は本体専用のため、独自トークンには使わないでください
- **形式は公式トークンと同じ HSL 裸トリプレット**を推奨します（使用側で `/10` 等の透過を掛けられます）
- **使用できるのはフォーク所有のコンポーネント内のみ**です（`brand/overrides/` / `brand/pages/`）。本体のコンポーネントが独自トークンを参照することはありません
- **Tailwind のユーティリティクラスは生成されません** — `theme.css` は `globals.css` と別の CSS ユニットのため `@theme` によるクラス生成が効きません。arbitrary value 記法で参照してください:

```tsx
<a className="text-[hsl(var(--brand-link))] bg-[hsl(var(--brand-accent-green))]">...</a>
```

### 本体画面の色を部分的に変えたい場合

オーバーライドしていない本体画面で「このコンポーネントだけ色を変えたい」場合、上の表のとおり公式トークンの上書きでは影響範囲が広すぎることがあります。このケースでは、本体側がコンポーネントスコープの**エイリアストークン**（例: `--kukan-header-bg`。デフォルトは `var(--primary)` を参照し、上書きしない限り挙動は変わりません）を追加する運用としています。必要になったら本体リポジトリへ issue で追加を提案してください。

## Tier 2: テキスト・メタデータの変更

`brand/brand-config.ts` を編集して、サイト名・著作権表示・メタデータを変更します。

```typescript
// apps/web/src/brand/brand-config.ts
import type { BrandConfig } from '@/types/brand'

export const brandConfig: BrandConfig = {
  siteName: '○○市オープンデータカタログ',
  siteDescription: '○○市が公開するオープンデータを検索・ダウンロードできます',
  copyright: '○○市.',
  copyrightUrl: 'https://www.city.example.lg.jp',

  logo: { type: 'image', src: '/brand/logo.svg', width: 160, height: 40, alt: '○○市' },

  headerNavExtra: [
    { label: '市公式サイト', href: 'https://www.city.example.lg.jp', external: true },
  ],
  footerLinks: [
    { label: '利用規約', href: '/terms' },
    { label: 'お問い合わせ', href: '/contact' },
  ],

  ogImage: '/brand/og-image.png',
  faviconPath: '/brand/favicon.ico',
}
```

### 各フィールドの説明

| フィールド        | 説明                                                |
| ----------------- | --------------------------------------------------- |
| `siteName`        | サイトタイトル（ブラウザタブ、ヘッダー等）          |
| `siteDescription` | meta description（検索エンジン向け）                |
| `copyright`       | フッターの著作権表示テキスト（`© 2026` は自動付与） |
| `copyrightUrl`    | フッターのサイト名リンク先（省略時はリンクなし）    |
| `logo`            | ヘッダーロゴの設定（後述）                          |
| `headerNavExtra`  | ヘッダーナビゲーションの追加項目                    |
| `footerLinks`     | フッターのリンク一覧                                |
| `ogImage`         | OGP 画像のパス（`public/` 配下のパス）              |
| `faviconPath`     | ファビコンのパス                                    |

検索例チップ（検索ボックス下のクエリ例）はブランド設定ではなく、**管理画面のサイト管理**（`/dashboard/admin/site`）から設定します。

### ロゴの設定

`logo` フィールドは 2 つのモードから選択できます。

```typescript
// デフォルト（KUKAN ロゴ）
logo: { type: 'default' }

// 画像ファイル（推奨: 高さ 32〜40px、SVG 形式）
logo: { type: 'image', src: '/brand/logo.svg', width: 160, height: 40, alt: '○○市' }
```

## i18n メッセージの上書き

UI に表示される翻訳テキストを組織ごとに変更できます。`brand/messages/{locale}.json` に上書きしたいキーだけを記述してください。

```json
// apps/web/src/brand/messages/ja.json
{
  "home": {
    "title": "○○市オープンデータカタログ",
    "description": "○○市のオープンデータを検索・活用できるポータル"
  }
}
```

```json
// apps/web/src/brand/messages/en.json
{
  "home": {
    "title": "City of Example Open Data Catalog",
    "description": "A portal to search and utilize open data from the City of Example"
  }
}
```

- 記述したキーのみ上書きされ、それ以外はデフォルト（`apps/web/messages/{locale}.json`）が使われます
- ネストされたオブジェクトは再帰的にマージされるため、兄弟キーを再記述する必要はありません
- 利用可能なキーの一覧は `apps/web/messages/ja.json` を参照してください

### `brandConfig` との使い分け

| 用途                               | 設定場所                       |
| ---------------------------------- | ------------------------------ |
| メタデータ・OGP 等（言語切替不要） | `brand-config.ts`              |
| UI 表示テキスト（言語ごとに変更）  | `brand/messages/{locale}.json` |

## Tier 3: コンポーネント差し替え

Header や Footer の構造自体を変更したい場合は、カスタムコンポーネントを作成して差し替えます。

### 手順

**1. カスタムコンポーネントを作成**

```tsx
// apps/web/src/brand/overrides/header.tsx
import { getCurrentUser } from '@/lib/server-api'
import { LanguageSwitcher } from '@/components/layout/language-switcher'
import { MobileNav } from '@/components/layout/mobile-nav'
import { UserMenu } from '@/components/auth/user-menu'

export async function Header() {
  const user = await getCurrentUser()

  return (
    <header className="sticky top-0 z-40 bg-[hsl(var(--primary))]">
      <div className="mx-auto flex h-[var(--kukan-header-height)] max-w-[var(--kukan-container-max-width)] items-center justify-between px-4">
        <img src="/brand/logo.svg" alt="○○市" className="h-8" />
        <div className="flex items-center gap-2">
          <LanguageSwitcher />
          {user && <UserMenu user={user} />}
          <MobileNav user={user} />
        </div>
      </div>
    </header>
  )
}
```

**2. `overrides/index.ts` に登録**

```typescript
// apps/web/src/brand/overrides/index.ts
import type { BrandOverrides } from '@/types/brand'
import { Header } from './header'

export const overrides: BrandOverrides = {
  Header,
}
```

これだけで Header が差し替わります。

### 利用可能なスロット

| スロット名 | 差し替え対象       |
| ---------- | ------------------ |
| `Header`   | サイトヘッダー全体 |
| `Footer`   | サイトフッター全体 |
| `TopPage`  | トップページ全体   |

### デフォルト部品の再利用

カスタムコンポーネント内では、本体のデフォルト実装をインポートして部分的に再利用できます。
循環参照を避けるため、`Header` ではなく `DefaultHeader` / `DefaultFooter` を使用してください。

```tsx
import { DefaultHeader } from '@/components/layout/header'
import { DefaultFooter } from '@/components/layout/footer'
```

### ファイルの階層化

override が増えた場合、ディレクトリで整理できます。

```
brand/overrides/
├── index.ts
├── layout/
│   ├── header.tsx
│   └── footer.tsx
└── pages/
    └── hero-section.tsx
```

`index.ts` で全て集約すれば、内部構造は自由です。

## 静的ページの追加

利用規約やプライバシーポリシーなど、組織固有の静的ページを追加できます。
初期状態ではサンプルの利用規約ページ（`/terms`）が含まれています。不要であれば削除してください。

### 手順

**1. `brand/pages/` にページコンポーネントを作成**

```tsx
// apps/web/src/brand/pages/privacy.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'プライバシーポリシー',
}

export default function PrivacyPage() {
  return (
    <article className="mx-auto max-w-3xl px-4 py-12">
      <h1 className="mb-8 text-2xl font-bold">プライバシーポリシー</h1>
      <p>...</p>
    </article>
  )
}
```

**2. `brand/pages/index.ts` に登録**

```typescript
export const pages: Record<string, () => Promise<BrandPage>> = {
  terms: () => import('./terms'),
  privacy: () => import('./privacy'), // 追加
}
```

これで `/privacy` にアクセスするとページが表示されます。

**3. 必要に応じて `brand-config.ts` の `headerNavExtra` や `footerLinks` にリンクを追加**

```typescript
headerNavExtra: [
  { label: 'プライバシーポリシー', href: '/privacy' },
],
footerLinks: [
  { label: '利用規約', href: '/terms' },
  { label: 'プライバシーポリシー', href: '/privacy' },
],
```

### ページの削除

不要なページは `brand/pages/index.ts` のマップから削除し、対応する `.tsx` ファイルを削除してください。

## 静的ファイルの配置

ロゴ、ファビコン、OG 画像などは `apps/web/public/brand/` に配置します。

```
apps/web/public/brand/
├── logo.svg
├── favicon.ico
└── og-image.png
```

配置したファイルは `/brand/logo.svg` のような URL で参照できます。

## 本体更新の取り込み

フォーク側は定期的に本体の `main` ブランチを取り込んでください。

```bash
git remote add upstream https://github.com/kukan-project/kukan.git
git fetch upstream
git merge upstream/main
```

カスタマイズが `src/brand/` と `public/brand/` に限定されていれば、コンフリクトは原則発生しません。

### コンフリクトが発生した場合

本体側が `src/types/brand.ts` に型を追加した場合、`brand-config.ts` で新しいフィールドの追加が必要になることがあります。TypeScript の型エラーとして検出されるので、エラーメッセージに従って対応してください。

## テスト

本体のユニットテストはブランド非依存に設計されており、テスト内では `src/brand/` の内容が KUKAN デフォルト値に固定されます。**ブランドをどうカスタマイズしても本体のテスト（CI）はそのまま通ります**。

- **本体のテストファイルは変更しないでください**。カスタマイズによって本体のテストが失敗する場合は、フォーク側で修正せず、本体リポジトリへ issue で報告してください
- **カスタムコンポーネント自体のテストは `apps/web/src/brand/__tests__/` に配置します**。`*.test.ts` / `*.test.tsx` は自動的に検出され、`pnpm test` で実行されます。テストを書くかどうかはフォーク側の裁量です

```tsx
// apps/web/src/brand/__tests__/header.test.tsx
import { describe, it, expect } from 'vitest'
import { render, screen } from '@testing-library/react'
import { Header } from '../overrides/header'

describe('Custom Header', () => {
  it('should render the organization logo', async () => {
    render(await Header())
    expect(screen.getByAltText('○○市')).toBeInTheDocument()
  })
})
```

## まとめ: カスタマイズの段階

| やりたいこと                       | 方法                                              | 所要時間の目安 |
| ---------------------------------- | ------------------------------------------------- | -------------- |
| 配色を変えたい                     | `brand/theme.css` に CSS 変数を記述               | 5 分           |
| 公式トークンにない独自色を使いたい | `brand/theme.css` に `--brand-*` トークンを定義   | 5 分           |
| サイト名・テキストを変えたい       | `brand/brand-config.ts` を編集                    | 30 分          |
| UI の翻訳テキストを変えたい        | `brand/messages/{locale}.json` に上書きキーを記述 | 10 分          |
| ロゴを差し替えたい                 | `public/brand/` にファイルを配置 + config 編集    | 10 分          |
| ヘッダー/フッターの構造を変えたい  | `brand/overrides/` にコンポーネント作成           | 数時間         |
| トップページを差し替えたい         | `brand/overrides/` にコンポーネント作成           | 数時間         |
| 静的ページを追加したい             | `brand/pages/` にコンポーネント作成 + 登録        | 30 分          |
